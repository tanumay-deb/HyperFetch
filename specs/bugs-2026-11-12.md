# Open bugs, 2026-11-12

Each was checked against the code (file and line as of `ca94399`). Fix them
one at a time, in this order unless told otherwise.

## Rules for whoever fixes these

- One bug, one commit. Message: `fix: <what the user sees now>`, a body that
  says why, and the bug's number from this list.
- Each fix comes with a test under `tests/` that FAILS on the code before the
  fix and passes after. Run that test file, then `pytest` (the whole suite,
  ~8 min) before pushing.
- Never edit `chrome_ext/`, `edge_ext/` or `firefox_ext/` without the user's
  yes.
- Tests and scripts never touch the real `%APPDATA%\HyperFetch` or the real
  temp folder (`tests/conftest.py` already isolates tests). Never run the
  real window against them.
- Read `AGENTS.md` and the Gotchas in `CLAUDE.md` before touching the
  engines: most "obvious" simplifications there were measured and are wrong.
- Fix the root cause in the shared function, not in one caller.

## Must

1. **Move to… leaves an unfinished download's bytes on the old drive.**
   `gui2/app_actions.py` `_move_task_files`: for an unfinished plain or stream
   (HLS) download it only changes `save_path` ("just retarget the
   destination"). The partial stays where `t.temp_path` says, so a download
   that failed because its drive is full fails again on every Resume (user's
   log, 18:34-18:36: `[Errno 28] No space left on device` after "Moved to
   H:/Jav"). Fix: when the partial (`t.temp_path`, see
   `utils.temp_download_path`) is on another drive than the new folder
   (`utils.same_drive`), pause it if running, wait for `t._worker_alive` to
   clear, move the partial with `utils.move_with_progress` to the new folder's
   temp place on a thread (as the torrent branch above it does), update
   `t.temp_path`, resume if it ran. Test: an unfinished task whose partial is
   "on another drive" (patch `utils.same_drive`) ends with its partial,
   byte-identical, under the new folder.

2. **A stream that fills the disk says only "disk error: [Errno 28] No space
   left on device".** `hls.py:919` writes the raw error. `downloader.py:536`
   already words disk-full ("disk full — N MiB free ..."); share it, name the
   drive, and say "free space there, or Move to… another drive and Resume"
   (true once 1 is fixed). Test: an ENOSPC while writing a segment gives that
   text.

3. **A non-range download cut short is marked Completed.**
   `downloader.py` `_transfer` (~1051): `all_done = ... else
   self.t.downloaded > 0`. A server that announced a size (HEAD
   Content-Length) and then sent a chunked body that ends early without an
   error passes as complete. Fix: with `total_size > 0`, require
   `downloaded >= total_size`, else ERROR ("the server ended the file early —
   Restart"). Test: local server, HEAD says N bytes, GET sends N/2 chunked and
   closes.

4. **A torrent from a web `.torrent` link (or one whose `.torrent` was
   deleted) cannot find itself in aria2.** `torrent.py` `_rpc_find_existing`
   (~2408) uses `infohash_for(self.t.url, self.t.filename)`, which knows only
   magnets and a `.torrent` that still exists. Resume then fails "InfoHash ...
   is already registered", and Move/Delete cannot make aria2 let go of the
   files. Fix: `task_infohash(self.t)`. Test: a fake daemon whose rows carry
   the task's saved `infohash`, task url `https://x/a.torrent`, returns the
   gid.

5. **Base32 magnets are never matched.** `torrent.py` `magnet_infohash`
   (~516) returns a 32-character base32 btih as is; aria2 and the metadata
   files use 40-hex. Same failures as 4, plus duplicate detection and cleanup.
   Fix: decode base32 (casefold) to 40-hex there; `scrape.infohash_bytes`
   already decodes it - one place for both. Test: the base32 and hex spelling
   of one hash give the same `magnet_infohash`.

## Should

6. **"System" theme on a light-mode Windows: dark-theme icons and toggles on
   light surfaces.** `gui/theme.py` `apply_theme` (~107) treats "system" as
   dark; `gui2/palette.set_theme` resolves it with `_system_is_light()`. Icons
   (`gui/icons._resolve_color`) and `AnimatedToggle` read `gui.theme`. Also
   `palette.set_accent` never updates `gui.theme.ACCENT`. Fix: resolve
   "system" once and give both modules the result; the accent too. Callers:
   `gui2/app_settings.py` 56/121/146. Test: "system" with a light Windows
   gives `gui.theme.TEXT` the light theme's text colour; a new accent reaches
   `gui.theme.ACCENT`.

7. **The details drawer's Resume on a Queued download does nothing.**

   ERROR under "resume"; `QueueManager.resume_task` ignores a queued task. The

   kept by two engines" first: the limit is shared between engines.

9. **Two copies of `resource_path`.** `gui/theme.py:34` and

10. **A YouTube error mentioning "403" anywhere reads as "bundled yt-dlp has
    gone stale".** `yt_dl.py` `explain`: `"403" in low` also matches a video

11. **The log tells a refused extension to "re-pair it from Settings".**
